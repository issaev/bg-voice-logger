# BG Voice Logger v0.3.0 — Документ за координация на акция

WordPress plugin + React интерфейс, Google Apps Script и Google Sheets за оперативни журнали на Спасителен клуб за бъдеще. Поддържа Google вход без WordPress акаунт, българска диктовка през браузъра, офлайн опашка, снимки към LOG, GPS в INFO, ръчна редакция и работни сесии.

**Статус:** тестова версия. Автоматичните тестове използват симулирани Google услуги. НЯМА потвърден интеграционен тест в реалния WordPress/Apps Script/Cloudflare/телефон. Не използвайте за единствен оперативен журнал при реална акция, докато не мине приемателен тест.

## Какво е ново спрямо 0.2.2

- **Google login:** Google Identity Services Web Client ID; JWT RS256 подписи се проверяват на WordPress сървъра по JWKS ключове на Google. Операторите нямат нужда от WordPress акаунти. Сесията е в HttpOnly cookie с HMAC и CSRF за записите. Текущият Google email трябва да е в allowlist, освен ако администраторът изрично е разрешил всички потвърдени Google акаунти. WordPress администратори с валидни права запазват административен достъп.
- **Транскрипция:** поправен lifecycle на SpeechRecognition (`bg-BG`), изчакване на финални резултати, ясни кодове на грешки, повторен старт при неочакван край (до два пъти), fallback към локален аудиозапис и ръчно въвеждане. Не използва платена AI услуга.
- **Опашка:** глобален екран за локалните операции; показва документ, таб, съдържание, статус и час; позволява изтриване на непратени/конфликтни/аудио записи с потвърждение, но не и в процес на изпращане или синхронизирани. Отделна база за всеки Google акаунт. Доброволен импорт на стари офлайн записи от гост-опашката на v0.2.2, без изтриване на източника.
- **Снимки:** от компютър, галерия или камера. Клиентско JPEG компресиране до 1600px и <=2.4MB, Blob в IndexedDB до синхронизация, качване в подпапка на акцията в Google Drive. В LOG!F се добавя RichText връзка към снимката. Прикачване към нов или съществуващ ред, с проверка срещу преместване/редакция.
- **GPS:** при създаване на акция именуването продължава да включва населеното място, но `INFO!B4` се **изчиства**. От таб INFO операторът може да поиска текущото местоположение (WGS84; `latitude, longitude` с шест знака) и да потвърди редакцията; при конфликт старите данни не се презаписват автоматично.
- **Канал:** гласовите записи се маркират в LOG!E с `Глас през приложението`; текстовият fallback — `Текст през приложението`.
- **Заглавие/лого:** „Документ за координация на акция“ и оригиналното лого на клуба, оптимизирано в WebP/PNG (без промяна на емблемата).

## 1. Инсталиране / обновяване

1. **Направете backup** на WordPress файловете/базата и на празния Google Sheet шаблон. Ако има чакащи локални записи, синхронизирайте ги преди обновяване или използвайте импорта след това. Никога не изчиствайте браузърното хранилище или инсталирано PWA, докато има непратени записи.
2. В WordPress: **Plugins → Add New → Upload Plugin → bg-voice-logger-v0.3.0.zip** и заменете съществуващата инсталация. PHP 8.3 е подходящ (изисква поне 7.4 за плъгина, но използвайте 8.3+ за WordPress екосистемата).
3. В Google Apps Script проект **BG Voice Logger Backend** заменете `Code.gs` с **пълния** файл `apps-script/Code.gs` от ZIP. Пазете Script Property `BVLOG_SHARED_SECRET` непроменена. **Deploy → Manage deployments → Edit → New version → Deploy**. НЕ създавайте нов deployment: старият `/exec` URL остава същият.
4. В WordPress → **Settings → BG Voice Logger** съхранените folder, template, `/exec` URL и shared secret трябва да останат непроменени. Натиснете **Test Google Connection** и очаквайте `complete / HTTP 200`.
5. В Google Cloud Console създайте **OAuth Client ID → Web application**. Authorized JavaScript origins: `https://spasitelenclub.com` (без `/dka/`), плюс тестов домейн, ако ползвате отделен. Настройте OAuth consent/branding според указанията на Google; при Testing добавете нужните тестови потребители. **Това е публичен Client ID, не Client Secret.**
6. Поставете `...apps.googleusercontent.com` в **Google OAuth Web Client ID**. Изберете **Application login mode: Google sign-in**. Добавете разрешените Google имейли (по един на ред). За достъп на всеки с Google акаунт можете да разрешите **Allow ANY verified Google account**, но това предоставя достъп до телефоните, логовете и снимките на всеки проверен Google акаунт и не се препоръчва. Запазете.
7. Изключете full-page кеширане на `/dka/` и кеширане на `/wp-json/bvlog/v1/*` в SpeedyCache/Cloudflare. След обновяване изчистете cache и Service Worker, само ако няма непратена локална опашка. Отворете в инкогнито и проверете Google входа.
8. **Важно:** За да се отварят качените снимки през Drive URL, Google операторите трябва да имат съответния Drive read достъп или да използват одобрена група; самият Google login в приложението не предоставя автоматично права на всички файлове в Drive.

### Настройки

| Ключ | Значение | По подразбиране |
|---|---|---|
| Working folder | ID/URL на папката с акции | `YOUR_DRIVE_FOLDER_ID` |
| Template Spreadsheet | ID/URL на празния шаблон | `YOUR_LEGACY_TEMPLATE_ID` |
| Apps Script URL | Статичен `/exec` URL | Запазва се от v0.2.2 |
| Shared secret | `BVLOG_SHARED_SECRET` | Запазва се; **не се споделя** |
| App page URL | URL на страницата с `[bg_voice_logger]` | `https://spasitelenclub.com/dka/` |
| Application login mode | `google`, `wordpress` или `public` | `google` (без публичен достъп по подразбиране) |
| Google OAuth Client ID | `...apps.googleusercontent.com` | празно; настройва се от админ |
| Approved Google emails | Разрешени акаунти | празно |
| Allow ANY Google account | Опасен публичен за всички потвърдени Google акаунти режим | Изключено |
| Allowed WP roles | Роли за WP fallback | `administrator,editor` |

## 2. Потребителски сценарий

1. Операторът влиза с одобрен Google акаунт без WordPress парола. При липса на internet може да продължи с кеширана своя идентичност от последните 12 часа, ако устройството има локални данни (без възможност за мрежови промени до повторен login).
2. Избира последната създадена акция (по подразбиране) или създава копие по образец `YYYY.MM.DD - ДКА - [тип акция] - [населено място]`.
3. По подразбиране отваря `LOG`: един голям микрофон, бързо текстово въвеждане, избор на снимки или камера, последни събития, постоянно видим брояч за локалната опашка.
4. Натиска микрофона → говори български → спира. Ако браузърът върне текст, той се записва **първо в IndexedDB**, после се синхронизира. Ако няма транскрипция, аудиото остава в опашката за прослушване/ръчно транскрибиране.
5. Ако е приложил снимка, след записването на LOG реда тя се качва в Google Drive и става линк в `LOG!F`. Може да добави снимка и към вече съществуващ ред.
6. В `INFO` полето **Локация** остава празно при нова акция. Бутон **GPS от телефона** предлага координатите и показва заявената точност; операторът потвърждава записването.
7. `TECH` и `TEAM` позволяват добавяне/редактиране с проверка на предишната стойност. Вторият блок на INFO се използва при смяна на ръководството на следващ ден.
8. При offline поведение операциите запазват оригиналното ID на документа; синхронизират се при връзка. Конфликтни редакции не се презаписват автоматично. В „Опашка“ се вижда към кой документ и таб се отнася всяка операция. Сесията може да се сменя без пренасочване на старите записи.

## 3. Техническа архитектура

```text
React (wp-element) + Browser MediaRecorder/SpeechRecognition/bg-BG
       | IndexedDB per Google user + Service Worker PWA shell
       | HTTPS same-origin REST + CSRF / Google session cookie
WordPress PHP /wp-json/bvlog/v1/
       | Google JS Identity JWT verification (JWKS RS256)
       | PHP Google bridge (shared secret, redirect GET handling)
Google Apps Script Web App Execute as Me
       | DriveApp: list, copy, per-incident image folder
       | SpreadsheetApp: LOG/INFO/TEAM/TECH, hidden UUID columns
       | LockService + hidden __BVLOG_OPS for retry idempotency
Google Sheets + Google Drive
```

Endpoint-ите на WordPress:

- `GET /auth/session` — проверка на Google/WordPress сесия и CSRF challenge (без чувствителни данни).
- `POST /auth/google` — получава GIS ID токен и го валидира по публични Google RSA ключове; проверява email allowlist; връща подписана HttpOnly сесия и CSRF token.
- `POST /auth/logout` — прекратява Google сесията.
- `GET /documents`, `POST /documents` — списък и нова акция.
- `GET /document/{id}` — четене на съществуваща акция и фото линкове.
- `POST /operation` — `log`, `field`, `add_row`, с уникален `op_id`.
- `POST /photo` — проверка MIME, размер и реални изображения; server-side relay на base64 към Apps Script; `log_op_id` или `target_row` + очаквани стойности.
- `GET /health` — тест `ping` (с приложна сесия; административният bridge test е отделен).

Apps Script операции: `ping`, `list`, `create`, `read`, `operation`. За `operation`, `kind=photo` създава файл в `Снимки - [spreadsheetId]` в работната Drive папка, добавя RichText линк към LOG!F и връща ID/URL. Има `op_id` за устойчивост при повторно изпращане; при дублиран файл по име същият файл се използва отново.

Не се публикуват Google credential или тайният bridge ключ в браузъра. Всяка публична операционна заявка се проверява от WordPress независимо от интерфейса.

## 4. Ограничения и рискове

- **Безплатната транскрипция не е гарантирана** във всички браузъри; SpeechRecognition често ползва външен онлайн engine, поддръжката на `bg-BG` варира. Web Speech API не приема готов аудиофайл за пакетна транскрипция. Запазеното офлайн аудио се транскрибира ръчно. Няма OpenAI/Google Cloud Speech платени услуги.
- `navigator.geolocation` работи само в защитена среда (HTTPS/localhost) с изрично разрешение. Телефонният GPS не е гарантирано точен — операторът трябва да провери координатите.
- Индексираните локални записи и снимки могат да бъдат изгубени, ако потребителят изчисти данните на браузъра или устройството. Работете на надеждно устройство и правете регулярни проверки/резервни копия.
- Google Drive изображенията може да са недостъпни за потребител, който няма Drive права, въпреки че приложението му разрешава логване. Права за преглед на снимки трябва да се настроят за съответната група.
- Няма транзакционно compare-and-swap спрямо ръчните редактори в Google Sheets: непосредствено преди запис се проверяват стойностите, но микропрозорец за съвпадение остава.
- За качване на снимки се изпраща компресиран JPEG през PHP към Apps Script; host HTTP timeout/Cloudflare 502 може да прекъсне отговора. Опашката запазва файла и retry с идентичния `op_id`. При необичаен 502 проверете Admin → Last Google bridge request; ако origin прекъсва PHP, може да се наложи промяна в хостинга/асинхронен job.
- Ако работната Drive папка е с `anyone: writer`, странични лица могат да променят таблиците/снимките независимо от Google Login. Настройте Drive sharing на Restricted и конкретни операторски групи.
- Премахване на Google акаунт от allowlist прекъсва и текущата му сесия. В режим Google няма анонимен REST достъп. Публичният режим е само за тестове с несекретни данни и изисква явен избор.

## 5. Приемателни тестове (задължителни преди продукция)

| ID | Проверка | Очакван резултат |
|---|---|---|
| AUTH-01 | Инкогнито, без WP login, одобрен Google акаунт | Успешен вход, вижда последната акция |
| AUTH-02 | Неодобрен Google акаунт | HTTP 403 и без достъп до REST данните |
| AUTH-03 | Logout, отворена REST заявка | 401/403, без достъп |
| VOICE-01 | Chrome Android, кратък гласов запис на български | Текст в LOG, оригинален час, коректен канал |
| VOICE-02 | Desktop Chrome, микрофон denied | Ясна грешка, без лъжливо „синхронизирано“ |
| VOICE-03 | Safari/неподдържан браузър | Резервен аудиозапис/текст, без загубен текст |
| QUEUE-01 | Airplane mode, 3 записи към две акции | Локална опашка с точни дестинации |
| QUEUE-02 | Delete на непратен запис | Изтрива само избрания локален запис, с потвърждение |
| QUEUE-03 | Google синхронизира, браузърът губи отговор | Повторно изпращане със същото UUID без дубликат |
| QUEUE-04 | Смяна на Google акаунт на същия телефон | Не вижда опашката на другия оператор |
| GPS-01 | Създаване на нова акция | Името съдържа населено място; `INFO!B4` е празно |
| GPS-02 | GPS позволен | Лат/лон с 6 знака, операторът потвърждава B4 |
| GPS-03 | Няма GPS разрешение | Обяснима грешка, без промяна на B4 |
| PHOTO-01 | Компютър: JPEG + нов LOG | Снимката е в Drive и LOG!F съдържа линк |
| PHOTO-02 | Телефон: камера/галерия | Същото; JPEG компресия работи |
| PHOTO-03 | Offline снимка, после reconnect | Файлът е запазен локално и качен след LOG |
| PHOTO-04 | Ръчна редакция/преместване на ред преди фото синхр. | Конфликт, не записва линк към грешен ред |
| PHOTO-05 | Двойно повторение на photo op | Само един файл и линк |
| DAY-01 | Събитие след полунощ | Само един разделител `ДАТА:` |
| INFO-02 | Нов ден и ново ръководство | Попълване на втория блок без промяна на първия |
| PARALLEL-01 | Един оператор в app, друг ръчно в Sheets | Новият LOG ред не изтрива ръчна промяна |
| PARALLEL-02 | Едновременна промяна на една INFO клетка | Конфликт / без автоматично презаписване |

## 6. Локални автоматизирани проверки

```bash
php -l bg-voice-logger.php
php -l includes/class-bvlog-auth.php
php -l includes/class-bvlog-api.php
php -l includes/class-bvlog-admin.php
node --check assets/app.js
node --check < apps-script/Code.gs
node tests/test-bridge.js
node tests/test-ui.js
node tests/test-public-ui.js
php tests/test-public-mode.php
php tests/test-google-auth.php
```

**Не е извършвана автоматична промяна на реалната Drive папка или шаблона от тази разработка.** Качването/подновяването на Apps Script Deployment, Google OAuth Client ID и интеграционното тестване са действия на администратора на сайта.
