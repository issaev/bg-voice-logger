# BG Voice Logger v0.4.0 — облачна транскрипция на български

**Модел:** Groq `whisper-large-v3`; резервен: Cloudflare Workers AI `@cf/openai/whisper-large-v3-turbo`.

**Статус:** реализирана и автоматизирано тествана интеграция с имитирани отговори на доставчиците. За да заработи с реално аудио, трябва да се настроят Cloudflare Worker и Groq акаунт. Реален тест с токени/аудио НЕ е извършван в тази разработка.

## 1. Технически поток

1. React PWA записва завършен аудиофайл чрез `MediaRecorder`. Преди мрежова заявка той се съхранява в IndexedDB към конкретната акция, оператор и време.
2. `POST /wp-json/bvlog/v1/stt/token` проверява сесията (Google или WordPress) и издава подписан HMAC билет с кратък срок (150 секунди), `op_id` и `doc_id`. Тук **не се изпраща аудио**.
3. Браузърът изпраща аудиото директно към Cloudflare Worker (HTTPS, multipart/form-data, Bearer ticket). Groq API ключът никога не е в браузъра/WordPress.
4. Cloudflare Worker проверява подписа/срока/произхода, rate limit и еднократния билет в Workers KV. Извиква Groq Large V3 (`language=bg`); при временна грешка опитва Workers AI Whisper V3 Turbo.
5. При успех приложението съхранява текста в **същия** локален запис и го изпраща като LOG операция през WordPress и Google Apps Script. UUID остава същият за избягване на повторен ред.
6. При липса на интернет или грешка аудиото остава в IndexedDB, видимо в „Локална опашка“. Повторните опити са с нарастващо изчакване; след четири неуспеха се предлага ръчен опит или транскрипция.
7. За диктовка в `INFO`, `TECH` или `TEAM` разпознатият текст се представя **за преглед**; не се редактира съответната клетка без потвърждение.

## 2. Подготовка

Нужни са:

- работещ WordPress v0.4.0 с Google Login за одобрени потребители;
- Cloudflare акаунт с Workers Free и Workers AI (без платен план);
- Groq Free акаунт и негов API key;
- локален Node.js 20+ и Wrangler CLI за първоначалното публикуване, или Cloudflare Dashboard с ръчно създадени bindings;
- стабилна HTTPS страница на приложението, например `https://spasitelenclub.com/dka/`.

Няма нужда от нов Google Apps Script deployment само за STT: съществуващият `Code.gs` остава непроменен.

**Защита на данните:** преди реални оперативни записи включете Zero Data Retention (ZDR) в Groq, ако настройката е налична за акаунта, и прегледайте условията за обработка и трансфер на лични данни. Не подавайте реални имена, телефони и съобщения за пострадали, докато не е одобрена тази обработка. Worker не записва аудио или транскрипции, но изпраща аудиото към доставчика за обработка.

## 3. Публикуване на Worker

В извлечения ZIP намерете директорията `bg-voice-logger/workers`.

```sh
cd bg-voice-logger/workers
cp wrangler.toml.example wrangler.toml
npx wrangler login
npx wrangler kv namespace create STT_NONCES
```

Копирайте `id`, който връща последната команда, в `[[kv_namespaces]] -> id` на `wrangler.toml`. Ако CLI не поддържа командата в този вид, създайте KV namespace през Cloudflare Dashboard и вземете ID оттам.

Проверете в `wrangler.toml`:

- `ALLOWED_ORIGIN = "https://spasitelenclub.com"` (без `/dka/`);
- `EXPECTED_ISSUER = "https://spasitelenclub.com"`;
- `AI` binding за Workers AI;
- `STT_NONCES` binding към правилния KV namespace;
- `STT_RATE_LIMIT` binding (20 заявки/минута на оператор, приблизителен лимит).

Създайте **отделна**, силна STT тайна. Например на собствен компютър:

```sh
openssl rand -hex 32
```

Не използвайте стария `BVLOG_SHARED_SECRET` от Google Apps Script. Запазете новата тайна в защитено място, след което добавете Worker секретите:

```sh
npx wrangler secret put STT_HMAC_SECRET
npx wrangler secret put GROQ_API_KEY
npx wrangler deploy
```

Worker ще бъде публикуван например на `https://bvlog-stt.<account>.workers.dev`.

Проверете **без никакъв токен**:

`https://bvlog-stt.<account>.workers.dev/health`

Очаква се JSON с `ok: true`, `primary: true`, `fallback: true`, `nonce_storage: true`. `/health` не доказва, че Groq реално е транскрибирал аудио.

## 4. Настройки в WordPress

WordPress → **Settings → BG Voice Logger → Cloud speech-to-text**:

| Поле | Стойност |
|---|---|
| Transcription mode | Cloud STT |
| Cloudflare Worker STT URL | `https://bvlog-stt.<account>.workers.dev/stt/transcribe` |
| Worker signing secret | Същата новосъздадена тайна като `STT_HMAC_SECRET` |

Запазете и презаредете `/dka/`. `BVLOG_STT_SECRET` може да бъде зададен и в `wp-config.php`, вместо тайната да се пази в WordPress база данни.

**Важно:** Google login/WordPress login е задължителен за облачната транскрипция. В приложен режим Public STT билет не се издава, за да се избегне неконтролируемо използване на безплатните API квоти.

## 5. Приемателни тестове

| ID | Действие | Очаквано |
|---|---|---|
| STT-01 | Кратък 10–20 s запис на български с интернет | Аудиото първо влиза в опашката, после се появява текст и се записва в LOG |
| STT-02 | Интернетът се спира преди запис | Аудиото остава в опашката, няма фалшиво потвърждение за Google Sheets |
| STT-03 | Възстановяване на връзката | Автоматична транскрипция и добавяне с оригиналния час |
| STT-04 | Groq връща временен 429/503 | При малък аудиофайл се опитва Workers AI, показва използвания доставчик |
| STT-05 | И двата доставчика отказват | Аудиото не се изтрива; статус и повторен опит |
| STT-06 | Потребителят диктува нов координатор в INFO | Показва транскрипцията за проверка, не записва автоматично |
| STT-07 | Два оператора в различни Google акаунти | Офлайн опашките остават разделени |
| STT-08 | Повторна операция след прекъсване | Само един LOG ред по UUID, без дублиране |
| STT-09 | Невалиден/изтекъл билет | 401; никаква заявка към Groq |
| STT-10 | Достъп от чужд origin | 403, без достъп до STT |
| STT-11 | Пауза, отказ, празна реч | Без измислено събитие, аудиото се запазва за проверка |
| STT-12 | Ръчно въвеждане на текст и снимка | Старият функционален поток работи |

**Праг:** преди продукция проведете поне 50 съгласувани реалистични български записи с контролен текст: шум, вътрешна радиовръзка, позивни, имена и координати. Сравнете резултатите с `tools/benchmark-stt.mjs` и измерете както WER, така и точността на числата. Симулационните тестове не доказват точност на българския модел.

## 6. Ограничения и защита

- Groq Free (по официални данни от ноември 2026): до 25 MB на файл; нашият Worker ограничава до 8 MB. Cloudflare резервният модел е ограничен умишлено до 2 MB на запис заради Free Worker CPU/памет.
- Worker Free има 10 ms CPU бюджет на заявка. В реални условия fallback base64 обработката може да не се побере в този бюджет. Нужно е реално тестване на различни аудиоформати и дължини.
- Cloudflare Workers KV Free допуска 1000 записа дневно; еднократните STT билети използват по един KV write на опит. KV е eventual-consistent: предотвратява повечето повторения, но не гарантира глобално атомарно "exactly-once" STT. UUID в Sheets е основната гаранция срещу повторен LOG ред.
- Cloudflare Rate Limiting binding е приблизителен, не абсолютен. За строги глобални разходни лимити би бил нужен Durable Object или централен брокер.
- Изразходването на безплатните квоти на Groq/Cloudflare води до грешка; приложението запазва аудиото. На Free plan не трябва да се конфигурира автоматично платено преминаване.
- Без интернет приложението може да запише аудио, но **не** може да изпълни облачната транскрипция. Безопасността на локалното хранилище зависи от устройството и браузъра; не изтривайте IndexedDB, докато има чакащи записи.
- Голямото аудио (>8 MB) не се качва. Изтеглете локалния файл и обработете ръчно или го разделете на по-кратки записи. Сега това е ограничение, а не автоматично транскрибиране на дълги записи.
- Това внедряване не решава самостоятелно предишните HTTP 502 при Google Apps Script bridge на SuperHosting: STT аудиото заобикаля PHP, но LOG записването продължава да използва WordPress/Apps Script.
